Code Reuse and the Open-Closed Principle

Slides: Code Reuse / Open-Closed Principle · reading: Agile Principles, Patterns, and Practices, OCP chapter

Two related goals

  • Avoid code duplication and design reusable code that works in several places in one project, or in several projects.
  • When the same or similar code is needed in several places, keep one copy that can be customized for each need.

The three primary ways to reuse code (review sheet)

WayHow it customizes behaviorExamples in this course
ParameterizationPass in what variesGeneric type parameters · pass in algorithms (Strategy) · pass in dependencies (Dependency Injection)
Implementation inheritanceSubclass and override or addOverride superclass methods (Template Method) · add methods and fields in a subclass
Composition / delegation (wrapping)Wrap an object and forward to itAdapter · Decorator

The Open-Closed Principle

"Software entities (classes, functions, libraries, etc.) should be open for extension but closed for modification."

  • Open: the entity's behavior can be extended or customized.
  • Closed: its source code doesn't have to be edited to do that.
  • Why avoid editing working code: you might introduce bugs into it, you might break code that depends on it (ripple effects), and the code might not even be yours to change (a library or framework).
  • Every technique in the table above is a way to follow OCP. Milestone 2 focuses on generics, inheritance, and Template Method.
Common trap: "closed" doesn't mean nothing new can be added. You add new code (a subclass, a new strategy, a new type argument) instead of editing the old code.

Template Method Pattern

Slides: Template Method Pattern · reading: GoF, Template Method · Template Method exercise

Problem

Duplicated code should live in one place: either a method that several clients delegate to (composition) or a superclass method that they inherit. But what if an algorithm is duplicated in several places and the copies are similar, not identical?

Solution

  • Put the common algorithm in a superclass method, the template method. It's concrete and fixes the order of the steps.
  • The steps that vary are abstract (usually protected) methods that the template method calls polymorphically.
  • Subclasses inherit the template method and implement the varying steps. They customize the algorithm without changing its structure.
  • From the GoF reading: the abstract steps are primitive operations. An optional step with a default (often empty) body that subclasses may override is a hook. The superclass calls the subclass, not the other way round (the "Hollywood principle": don't call us, we'll call you). Subclasses normally shouldn't override the template method itself.
abstract class Game {
  playOneGame(playersCount: number): void {      // template method
    this.initializeGame();
    let currentPlayer = 0;
    while (!this.endOfGame()) {
      this.makePlay(currentPlayer);
      currentPlayer = (currentPlayer + 1) % playersCount;
    }
    this.printWinner();
  }
  protected abstract initializeGame(): void;      // varying steps
  protected abstract makePlay(player: number): void;
  protected abstract endOfGame(): boolean;
  protected abstract printWinner(): void;
}

class Monopoly extends Game {
  protected initializeGame() { /* players, money */ }
  protected makePlay(player: number) { /* one turn */ }
  protected endOfGame() { return false; /* Monopoly rules */ }
  protected printWinner() { /* show winner */ }
}

Refactoring steps (from the slides)

  1. Make the similar code in each class as similar as possible.
  2. Create a common base class for those classes.
  3. Move one copy of the code into the base class. It becomes the template method.
  4. Identify the code that varies by subclass.
  5. Create abstract methods for the varying code.
  6. Replace the varying code in the template method with calls to those abstract methods.
  7. Override the abstract methods in each subclass with its version of the varying code.

Where you've used it

  • Exercise: LineCount and FileSearch both walk a directory (optionally recursively), skip unreadable files, process each matching file, then print a total. The base class keeps the walking; each subclass supplies "process one file" and its totals.
  • Tweeter M2B: similar presenters (for example the paged followee/follower/feed/story presenters) share one template that loads a page of items and differ only in the service call and item description. The M2C report asks you to diagram this before and after.
Template Method vs. Strategy (coming later): both vary steps of an algorithm. Template Method uses inheritance (override in a subclass). Strategy uses composition (pass in an object, swappable at runtime).

Generic Programming

Slides: TypeScript Generics · reading: Programming TypeScript, "Polymorphism" · Generics exercise

Why

A function typed for string[] only works on strings. Typing it any[] works on everything but turns off type checking. A type parameter is a placeholder for a type chosen when the code is used, so one copy works for every type and stays type-checked.

function filter<T>(array: T[], predicate: (value: T) => boolean): T[] { … }
function map<T, U>(array: T[], f: (item: T) => U): U[] { … }   // two type parameters

map(["1", "2"], s => parseInt(s));   // T = string, U = number (inferred)

Where generics can appear

KindExample
Function, function expression, arrow function, object methodconst filter = <T>(a: T[], p: (v: T) => boolean): T[] => …
Classclass Pair<T, U> { constructor(private value1: T, private value2: U) {} }
Subclass fixing some parametersclass KeyValuePair<V> extends Pair<string, V> · class StringPair extends Pair<string, string> (not generic)
Type aliastype Predicate<T> = (value: T) => boolean;
Interfaceinterface List<T> { add(v: T): void; filter(p: Predicate<T>): T[]; map<U>(f: MapFunction<T, U>): U[] }

Type arguments can be written explicitly (new Pair<string, number>("Hello", 123)) or inferred from the arguments (new KeyValuePair("Hello", new Date())).

Constraints

type Sortable = string | number | bigint | boolean | Date;
function sort<T extends Sortable>(array: T[]): void { … uses > … }

interface Comparable<T> { compareTo(value: T): number; }
function sortObjects<T extends Comparable<T>>(array: T[]): void { … a.compareTo(b) … }
class Person implements Comparable<Person> { compareTo(p: Person) { return this.name.localeCompare(p.name); } }
  • T extends X means "T must be structurally compatible with X", not necessarily a subclass.
  • A constraint lets the generic code safely use members (like compareTo or >) that every allowed type has.
  • Person implements Comparable<Person> makes the contract explicit, so the compiler checks Person against it where Person is declared.
  • Types are erased when TypeScript compiles, so generic code can't do new T() or x instanceof T.

Exercise and Tweeter

  • Drawer<T> holds one kind of clothing; Dresser<T, U, V> has three typed drawers.
  • Cat and Dog's duplicated static methods become generic methods on Animal: static getSorted<T extends Animal>(list: T[]): T[].
  • Milestone 3's ClientCommunicator.doPost<REQ extends TweeterRequest, RES extends TweeterResponse> is one generic method for every endpoint.

Design Principles

Reading: "Principles of Software Design" · The Ten Design Commandments · Design Principles exercise

Design is mostly about managing complexity. Goals: software that works, is easy to read, debug and maintain, holds up under change, and is reusable.

PrincipleWhat it saysKnow for the exam
SimplicityAs simple as possible, but not simpler. Don't add classes, parameters or levels "for later".YAGNI: you aren't going to need it. Refactor when the feature actually arrives.
Avoid code duplicationDRY. Put shared code in one place: a private method, a shared class, a superclass, or a generic.Costs: change N copies, a bug is copied N times, longer code. Another benefit of removing it: duplication usually signals a missing abstraction, so removing it leads to a better design (and reusable code).
OrthogonalityUnrelated things are independent: change A without affecting B (UI vs. database). Helicopter controls are the non-orthogonal example.Achieved through the Single Responsibility Principle and minimizing dependencies.
Single ResponsibilityA class has one reason to change; a method does one well-defined task.Related terms: cohesion, separation of responsibility.
Minimize dependenciesA depends on B if it calls B, reads B's state, inherits from B, takes a B parameter, or shares global data/files with B.Fewer dependencies: easier to understand, fewer ripple effects, easier reuse. "Shy code": ask for what you need (plotDate(date, timeZone)) instead of chaining sel.getRecorder().getLocation().getTimeZone(). Goal is to minimize, not eliminate.
DecompositionDivide and conquer, top-down: system → subsystems → packages → classes → methods.Hypo-decomposition (too little, e.g. one giant class) is the common mistake; hyper (e.g. a Digit class) is rare. Three ways to tell you've gone far enough: SRP, size/length metrics, complexity metrics.
High-quality abstractionGood names (classes are nouns, methods verbs); abstract all the way / avoid primitive obsession.Make a class instead of a primitive for: domain checking (validate in the constructor), a place for additional operations, and readability of types.
Information hidingHide implementation details so others can't depend on them.Four ways: visibility (private by default), naming (search not binarySearch, ClassRoll not StudentLinkedList), separate interface from implementation, data hiding.
Depend on abstractionsDeclare variables and parameters with interfaces or abstract classes, not concrete classes.new and static method calls are concrete dependencies; use factories or dependency injection. Makes code testable with mocks.
Isolated changeOne responsibility implemented in one place (the reverse direction of SRP).Avoid "shotgun surgery". E.g. all database code in one data-access package; XML → JSON only touches one class.
Testable codeCommandment 9.Follows from depending on abstractions and minimizing dependencies.
Error handlingOn an error, a method should recover, return it to the caller, or log it.Never silently swallow it (empty catch). Document the errors a method can return.
Algorithm & data structure selectionPick ones with good time and memory behavior for the data.No amount of decomposition hides an O(n³) algorithm on big data.

The review sheet's code question

void f(ArrayList<String> names) {
    for (int i = 0; i < names.size(); i++)
        names.set(i, names.get(i).toUpperCase());
}

It violates depend on abstractions, not concretions: the method only needs list operations, but it can only accept an ArrayList. Fix: declare the parameter as the List<String> interface so any list (LinkedList, a test double) can be passed.

Data hiding benefits

Freedom to change data structures without affecting clients · a convenient method interface · protects data integrity · allows internal optimizations (e.g. indexes).

Why fake ("mock") objects

  • A unit test tests one class in isolation. The test driver runs test cases against the code under test, which talks to mock objects instead of its real dependencies. An integration test tests real components together (Milestone 3's ServerFacade tests).
  • Real dependencies can be buggy, slow, nondeterministic, or need a network, database or AWS. Fakes isolate the code under test, keep tests fast and repeatable, and let you control and observe its interactions.

What mock objects can do (slides): do nothing · validate the method inputs · validate the method call sequence, including parameter values · send a message to a log · return a hard-coded answer regardless of input · select an answer from a pool of hard-coded answers (cycling or at random) · randomly generate an answer · prompt the user for the answer · act as a simple implementation that is slower, less accurate or less capable than the real module · pause to simulate the real module's time · generate errors (throw exceptions) that are hard to produce for real.

Mocks vs. spies (ts-mockito)

MockSpy
What it isAn object that implements a type's public interface (methods and properties)An object that wraps a real object; its interface mirrors the wrapped object
By defaultMethods do nothing (unstubbed calls return null) and properties are undefinedMethods and properties delegate to the real object

  • when(...) sets up behavior before the code runs (arrange). verify(...) checks how a mock was used after it runs (assert).
  • You can mock regular classes, abstract classes, generic classes and interfaces. For an interface, use the type argument form: mock<FooInterface>(), not mock(FooInterface), because interfaces don't exist at runtime.
ts-mockitoMeaning

React component testing (@testing-library)

Write tests that check a component renders correctly (updates the DOM properly), updates state correctly, and fires events correctly.

import { render, screen, act } from "@testing-library/react";
import "@testing-library/jest-dom";
import userEvent from "@testing-library/user-event";
import { MemoryRouter } from "react-router-dom";

test("fires onButtonClick events", async () => {
  const onButtonClick = jest.fn();
  render(
    <MemoryRouter>                       {/* router context for Link etc. */}
      <MyComponent page="http://www.facebook.com" onButtonClick={onButtonClick}>Facebook</MyComponent>
    </MemoryRouter>
  );
  const user = userEvent.setup();

  const myButton = await screen.findByText(/Press Me/);
  expect(myButton).toBeEnabled();

  await act(async () => { await user.click(myButton); });
  expect(onButtonClick).toHaveBeenCalledTimes(1);
});
  • render(...) returns { container }; screen finds elements by test id (data-testid="my-input" → findByTestId("my-input")), text, role or label.
  • jest-dom matchers: toBeEnabled, toBeDisabled, toHaveAttribute("href", url), toContainHTML("Facebook"), toBeInTheDocument.
  • Wrap user actions in act(async () => { await user.type(input, "a"); }) so React finishes updating before you assert.

Cloud Computing and AWS

Cloud computing lecture notes · AWS "What is cloud computing?" · AWS S3 exercise
  • Cloud computing: rent someone else's IT infrastructure instead of buying and maintaining your own. Add or remove capacity as needed and pay for what you use.
ModelYou rentYou manage
IaaSVirtual machines, networks, storage, databasesConfiguring and installing everything yourself
PaaSA platform that deploys and scales your app (e.g. point it at your Git repo)Just the application
ServerlessYour handler code runs whenever a request arrives; no server program or machine to manageJust the handlers and supporting code. A serverless database exposes web APIs for CRUD, with no database server to run.

Three ways to use AWS

  1. Web console: manage resources interactively in a browser.
  2. CLI: do (almost) anything the console can from a terminal, so tasks can be scripted and automated. Set up with an IAM user and long-term access keys (aws configure).
  3. SDK: write programs that create, manage and use resources.

S3 (cloud file storage)

  • Files are objects stored in buckets and named by a key (the file name or path). Buckets live in a region.
  • CLI: aws s3 mb s3://my-bucket, aws s3 cp notes.txt s3://my-bucket/notes.txt.
import { S3Client, PutObjectCommand } from "@aws-sdk/client-s3";

const client = new S3Client();   // uses the credentials and region set up for the CLI
const response = await client.send(new PutObjectCommand({
  Bucket: "my-bucket",
  Key: "uploads/notes.txt",
  Body: fs.readFileSync("notes.txt"),
}));
console.log(response.$metadata.httpStatusCode);   // 200 on success

AWS services this course uses: S3 (files), Lambda (serverless handlers), API Gateway (web APIs that call Lambdas), DynamoDB (serverless database), SQS (asynchronous processing). SDK v3 pattern: make a client, build a command, await client.send(command).

Serverless, Lambda, and Security (IAM)

Topic page · Lambda Developer Guide · AWS Lambda exercise · Milestone 3

Lambda

  • Functions that AWS runs automatically in response to events: HTTP calls (through API Gateway), file uploads, database changes, a schedule. You upload code and say when it should run; there's no server to manage.
  • The handler receives the event (JSON deserialized into an object) and returns a result (serialized to JSON). Throwing an error marks the invocation as failed.
export const handler = async (event: EmailRequest): Promise<EmailResponse> => {
  try {
    await sesClient.send(createSendEmailCommand(event));
    return new EmailResponse("Email sent.", getFormattedDate());
  } catch (e) {
    throw Error("Failed to send email. " + e);
  }
};

Deploying (the exercise)

  1. npm run build (tsc) → zip the contents of dist, not the folder itself.
  2. Create the function: runtime Node.js 20.x, execution role = your IAM role.
  3. Handler setting = file path without extension + exported name, e.g. dist/lambda/EmailSender.handler (depends on how you zipped).
  4. Upload the zip. tsc doesn't bundle node_modules, so add a Lambda layer: a zip of nodejs/node_modules/… with a matching runtime.
  5. Test with a test event (a JSON object sent as the event). console.log output goes to CloudWatch Logs.

IAM (Identity and Access Management)

ThingWhat it is
UserA person or program with long-term credentials (your admin user and its access keys for the CLI/SDK)
GroupA set of users that share permissions
RoleA set of permissions that a trusted entity assumes, such as the Lambda service; no password or long-term keys
PolicyA JSON document granting or denying permissions, attached to users, groups or roles
  • The exercise's execution role: trusted entity = AWS service, use case Lambda; policies AmazonSESFullAccess (send email) and CloudWatchLogsFullAccess (write logs). Without the logs permission, you don't see logs.
  • Best practice is least privilege: grant only what's needed. "Full access" policies are a classroom shortcut.
  • SES only sends to and from verified identities by default.
  • Milestone 3: one Lambda per feature (14). Each handler is thin and delegates to the service layer on the server.

API Gateway and HTTP Client Access

Topic page · API Gateway exercise, FAQ, and "Mapping Exceptions to Error Codes" · Milestone 3

API Gateway lets clients call your Lambda functions over HTTP. Instead of writing your own server (as in CS 240), you define a web API and connect each endpoint to a Lambda.

ConceptMeaning
REST API (Regional)The API you create
ResourceA URL path, e.g. /sendemail; {to} marks a variable segment (/sendemail/{to}/{from})
MethodAn HTTP verb on a resource (POST) with an integration, here a Lambda function
Method requestDeclares what callers send, e.g. required headers EmailSubject, EmailText
Integration requestBuilds the Lambda's input. A mapping template (for application/json) maps URL params and headers into the JSON event: "to": "$input.params('to')"
Integration responseMaps the Lambda's result or error to a status code, using a Lambda error regex
Method responseDeclares the status codes (200, 400, 500), models, and headers (CORS) the method can return
Stage / deployChanges reach the outside world only after you deploy to a stage (e.g. dev). Invoke URL: https://{api-id}.execute-api.{region}.amazonaws.com/dev/sendemail
CORSLets a browser page from another origin call the API (preflight OPTIONS, Access-Control-Allow-Origin header). Enable it on each resource and on each error response. curl and Postman don't test it.
Docs / SwaggerAdd method descriptions, publish documentation, export the API as a Swagger (OpenAPI) file. API Gateway can also generate client SDKs.

Error codes

  1. The Lambda throws an error whose message starts with a tag: throw new Error("[Bad Request] requested user does not exist").
  2. Method response: add 400 and 500 (and optionally 401) with the Error model.
  3. Integration response: regex ^\[Bad Request\].* → 400 (escape the brackets; mind the space). Add the catch-all .* → 500 last. Without it, a mistyped error can come back as a false 200.
  4. Redeploy, and test from the method's Test page.

Troubleshooting (exercise FAQ)

  • Unauthorized / not found: URL missing the stage or the resource path, or {to}/{from} placed wrong.
  • 502: Lambda Proxy Integration turned on (turn it off for the course), or the request/response shape doesn't match what the Lambda expects or returns.

Tweeter Milestone 3: calling the API from the client

  • Use POST for every endpoint with the auth token in the JSON body; it keeps API Gateway setup much simpler. Request/response classes live in tweeter-shared.
  • New client network layer: client Services call a ServerFacade (Facade pattern, one method per endpoint), which calls a ClientCommunicator that does the actual fetch.
// ClientCommunicator (simplified)
async doPost<REQ extends TweeterRequest, RES extends TweeterResponse>(req: REQ, endpoint: string): Promise<RES> {
  const resp = await fetch(this.SERVER_URL + endpoint, {
    method: "POST",
    headers: new Headers({ "Content-type": "application/json" }),
    body: JSON.stringify(req),
  });
  if (resp.ok) return (await resp.json()) as RES;
  const error = await resp.json();
  throw new Error(error.errorMessage);
}

// ServerFacade
async getMoreFollowees(request: PagedUserItemRequest): Promise<[User[], boolean]> {
  const response = await this.clientCommunicator.doPost<PagedUserItemRequest, PagedUserItemResponse>(request, "/followee/list");
  const items = response.success && response.items ? response.items.map(dto => User.fromDto(dto) as User) : null;
  if (response.success && items) return [items, response.hasMore];
  throw new Error(response.message ?? "No followees found");
}
